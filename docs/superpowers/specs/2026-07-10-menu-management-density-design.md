# 菜单管理密度收敛设计

## 背景

“成员与部门”已形成紧凑、可扫描的标准密度，而“菜单管理”在业务页局部叠加了多组固定最小高度、大内距和嵌套背景块。基础 Button / Input 的高度仍与全局一致，失衡来自顶部子系统切换、左侧菜单树和右侧详情容器。

## 目标

- 以成员表格和已收敛的角色详情为密度基准。
- 同时收紧子系统切换、菜单树工作区和节点详情，避免只改一栏导致新的比例断层。
- 保留双行菜单节点信息、常驻详情/窄屏 Sheet、展开折叠和行内编辑能力。
- 不修改全局显示比例、Button / Input / Select 默认 token 或菜单数据流。

## 方案对比

### A. 业务层容器密度收敛（采用）

保留现有信息架构，只收敛固定高度、内距、图标盒和卡片间距。菜单树行使用接近表格的紧凑高度；详情头、基本信息字段和按钮权限行收紧为同一垂直节奏。

优点：修复根因，影响面仅限菜单管理，不破坏其他页面。

### B. 下调全局控件和表格 token（不采用）

直接改小 `--control-*` 或 `--table-row-h`。

问题：基础控件当前尺寸正常，这会连带改变成员、角色及其他业务页。

### C. 对菜单页整体做局部缩放（不采用）

通过 `transform: scale()` 或类 zoom 机制缩小整页。

问题：会破坏点击区域、滚动容器、Sheet / Dialog 定位和 `--app-scale` 三档合同。

## 尺寸约束

### 子系统切换

- 子系统项从约 62px 收紧到 52px，保留名称和类型/状态两行。
- 图标盒从 32px 收紧到 28px，减少横向宽度和卡片内距。
- “新增子系统”与切换项同高。

### 菜单树工作区

- 工具条与搜索区从约 55px / 59px 收紧到 46–52px。
- 菜单树行从 52px 收紧到 44–48px，保留名称 + id 两行，不裁切文字。
- 节点图标盒从 32px 收紧到 28px；展开/新增按钮仍使用现有 `icon-xs`。
- 保留展开折叠动画，行级 hover 保持即时，不重新引入 `transition-colors`。

### 右侧节点详情

- 常驻详情外距改用现有 `--page-scene-px` / `--page-scene-py`。
- 详情头从约 68px 收紧到 52–56px，图标盒从 40px 收紧到 32px。
- 基本信息卡内距从 16px 收紧到 12px，字段行从 64px 收紧到约 48px。
- 按钮权限卡和动作行同步减少外距、内距与行高。
- 窄屏 Sheet 复用同一内容组件，不另造一套密度。

## 交互与数据边界

- 不改子系统切换、搜索、树节点选中、展开折叠、可见性切换和增删改逻辑。
- 不改 TanStack Query key、失效策略、权限判断或表单 schema。
- 不改 Dialog / Sheet 的交互合同。

## 验收标准

1. 子系统切换、树工具条、搜索区、菜单树行、详情头和字段行均显著低于现状。
2. 菜单树和详情仍具有清晰的名称、id、类型、路由、权限和可见性层级。
3. 基础 Button / Input / Select 高度不变，已有操作、键盘可达性和权限边界不变。
4. 90% / 100% / 108% 三档下无水平溢出，右侧行内编辑器和窄屏 Sheet 保持可用。
5. 新密度测试先失败，实现后通过；再运行角色与菜单相关测试、全量测试、主题守卫、类型检查、Lint 和生产构建。

## 非目标

- 不改菜单管理信息架构。
- 不修改全局基础组件 token。
- 不改菜单 mock / API / schema / Query 逻辑。
- 不处理其他 Admin 页面的密度问题。
