# Claude Design 参考下的紧凑企业后台默认视觉设计

日期：2026-07-29  
状态：待评审  
范围：`frontend/` 视觉基础层、Shell、通用 UI/Pro 组件及代表性页面

## 1. 目标

参考 Claude Design 打单系统原型的视觉节奏，重做 MetaBuilder 的默认密度与层级，使它在 1440×900 的常见办公屏幕上：

- 同屏承载更多有效业务信息；
- 字号、图标、间距、分割线和卡片比例更协调；
- 保持企业后台所需的可读性、可访问性和交互热区；
- 让后续业务项目通过基础组件和 token 自动获得一致质量，而不是继续在业务页面复制视觉类。

本次不是复刻参考原型，也不是把全站缩放到 90%。参考原型提供视觉尺度和信息组织经验，现有架构、组件边界、主题能力与可访问性要求仍以本项目为准。

## 2. 现状与基线

1440×900、100% 显示比例下的实测对比：

| 项目 | Claude Design 参考 | MetaBuilder 当前 | 设计结论 |
| --- | ---: | ---: | --- |
| 顶栏高度 | 52px | 56px | 默认收敛到 52px |
| 侧栏宽度 | 198px | 232px | 通用脚手架取 208px，兼顾更长菜单 |
| 一级导航行高 | 约 33px | 42px | 收敛到 36px |
| 导航图标 | 15px | 18px | 收敛到 16px |
| 导航文字 | 12.5px | 14px | 收敛到 13px |
| 页面水平留白 | 22px | 28px | 收敛到 22px |
| 表头高度 | 38px | 48px | 收敛到 40px |
| 表格正文行高 | 44px | 44px | 保留 44px |
| 表格正文文字 | 12.5px | 14px | 收敛到 13px |
| KPI 卡片高度 | 约 92px | 约 164px | 统一到 96–112px |
| 常用按钮 | 30–31px | 30–32px | 基本保留 |

参考原型的弱灰文字在白底上的对比度不足，不直接复制其颜色值。紧凑化只调整信息层级与几何，不以牺牲可读性换取“像”。

## 3. 方案选择

### 采用：系统级紧凑默认

统一调整 Shell、页面骨架、卡片、表格和排版 token，并用代表性页面验证基础层是否真正生效。

优点：

- 后续业务模块自然继承；
- 与现有 token、主题 flavor、`components/ui`、`components/pro` 架构一致；
- 可通过状态矩阵和守卫防止回退。

### 不采用：只改代表性页面

短期截图变化快，但会把视觉实现继续留在业务页面，后续复制成本和风格漂移都更高。

### 暂不采用：新增运行时密度开关

现有 `--app-scale` 已负责 90% / 100% / 108% 显示比例。再增加一条密度轴会显著扩大 flavor、主题、比例、导航布局的组合矩阵。当前先建立一个质量足够高的默认密度，待真实项目出现明确的宽松模式需求后再评估。

## 4. 设计原则

### 4.1 密度不等于缩放

- `--app-scale` 继续只承担用户显示比例；
- 默认视觉密度通过各组件族的尺寸 token 调整；
- 禁止用 CSS `zoom`，禁止把默认比例改成 90% 冒充紧凑设计；
- 90% / 100% / 108% 三档仍应在新的默认密度上等比成立。

### 4.2 减少装饰，增强层级

- 主要依靠空间、字号、字重和少量分割线区分层级；
- 弱化大面积灰底、厚边框、重阴影和彩色图标底座；
- 卡片默认使用低对比边框与轻阴影，避免每个信息块都像独立弹窗；
- 状态色只表达状态，不承担普通信息分组。

### 4.3 交互尺寸与信息尺寸分离

- 表格、导航和说明文字可以更紧凑；
- 输入框、常用按钮和可点击热区不做激进压缩；
- 图标视觉尺寸可减小，但焦点、hover、active 和键盘可达性必须保留；
- 普通正文不复制参考原型中低对比度的弱灰。

### 4.4 基础层治理

- 业务页面只负责布局和业务组合；
- 通用视觉状态进入 `components/ui` 或 `components/pro`；
- 同类 KPI/统计卡模式已跨多个页面重复，达到抽象阈值，应形成业务无关的 Pro 组件；
- 改动基础组件时同步更新 `/dev/theme-states` 和 guard。

## 5. 视觉规格

### 5.1 Shell

- 顶栏：52px；
- 侧栏展开宽度：208px，折叠宽度保持现有语义；
- 一级导航：36px 行高、16px 图标、13px 字号；
- 二级导航：34px 行高、13px 字号；
- 顶栏与侧栏分割线使用 Shell 语义 token，不直接复用业务卡片边框；
- 顶栏搜索、用户入口、子系统切换器跟随 52px 高度重新校准垂直居中。

其他导航布局不重新设计，但必须确保侧栏模式的 token 调整不会破坏 Inset 和 Rail 布局。

### 5.2 页面骨架

- 页面水平内距：22px；
- 页面垂直内距：16px；
- 面包屑与主体间距：12px；
- 页面标题：18–20px，依据标题层级由 Pro 组件提供；
- 页面区块间距：16px；
- 筛选区、操作区、表格之间优先使用 12–16px 间距；
- 避免为制造“卡片感”给每个区块重复添加背景、边框和大圆角。

### 5.3 卡片与 KPI

- 通用卡片默认内距：16px；
- 普通卡片圆角使用现有 token，默认视觉目标约 10px；
- KPI 卡高度目标：96–112px；
- KPI 主数值：24–28px，行高紧凑；
- KPI 标签：12–13px；
- 辅助趋势与说明：11–12px，但必须满足颜色对比度；
- 图标默认 16–18px，不再使用大面积彩色方块承托；
- 彩色背景只保留给确有语义的告警或状态。

新增 `components/pro` 统计卡组件，覆盖标题、数值、趋势、辅助说明和可选图标；Dashboard、尾程概览及其他已出现同类模式的页面逐步迁移。

### 5.4 表格

- 表头高度：40px；
- 正文行高：44px；
- 表头字号：12px，正文：13px；
- 单元格水平内距：12–14px；
- 表头使用低对比背景或纯白加分割线，不使用厚重色块；
- 分割线分为表头边界、正文行分割和外框三个语义层级；
- 多行业务信息通过 13px 主信息 + 11–12px 次信息承载，不通过继续增高行高解决；
- DataTable、TableShell 和 `ui/table` 必须共享同一组几何 token。

### 5.5 颜色与边界

建立并校准以下四类边界语义：

1. Shell 分隔；
2. 页面区块分隔；
3. 卡片外框；
4. 表格行分隔。

这些语义由对应组件族 token 消费。禁止业务页面用 `border-border` 或硬编码颜色模拟通用层级。

正文、次要信息、占位信息至少形成三级文字层级；正常尺寸正文优先满足 WCAG AA 对比度，不复制参考原型中低对比弱灰。

## 6. 实现边界

第一阶段只做前端视觉与组件治理，不处理后端、数据契约和业务流程。

基础层改动：

- `styles/tokens.base.css`：默认密度与组件族 token；
- 各 flavor：仅保留风格差异，避免用 flavor 重复定义统一密度；
- Shell：顶栏、侧栏、导航项与关联入口；
- `components/ui`：Card、Table 等原语；
- `components/pro`：PageScaffold、DataTable、TableShell、统计卡；
- `/dev/theme-states`：新增或补全相关状态矩阵；
- guard：约束业务层不得重新引入通用视觉状态。

代表性页面：

- 管理后台 Dashboard：验证 KPI、卡片和信息层级；
- 用户列表：验证页面骨架、筛选、表格和分页；
- 尾程 Overview：验证通用统计卡在业务子系统中可复用。

不在第一阶段做：

- 新增密度设置项；
- 全量逐页手工改样式；
- 更换 Radix/shadcn primitives；
- 复刻 Claude Design 源代码或颜色；
- 移动端专项重设计；
- 修改后端或业务规则。

## 7. 执行顺序

1. 为新增 token、组件归属和业务层禁用规则补守卫；
2. 调整默认 token 与 Shell 几何；
3. 统一 Card、Table、PageScaffold；
4. 新增通用统计卡并迁移 Dashboard；
5. 验证用户列表与尾程 Overview，修复基础层遗漏；
6. 更新 `/dev/theme-states`；
7. 执行静态门禁、单测、构建和真实浏览器视觉验收；
8. 将视觉结论与截图路径写回本规格。

## 8. 验收标准

静态门禁：

```bash
cd frontend
./node_modules/.bin/tsc -b --noEmit
./node_modules/.bin/eslint src
./node_modules/.bin/vitest run
pnpm theme:guard
node scripts/design-md-lint.mjs
```

若涉及生产构建：

```bash
./node_modules/.bin/tsc -b
./node_modules/.bin/vite build
```

并检查 `dist` 不包含 `faker`、`msw`、`mockServiceWorker`。

真实浏览器验收：

- 1440×900；
- 飞书默认 flavor；
- 亮色与暗色主题；
- 侧栏布局；
- 90% / 100% / 108% 三档显示比例；
- Dashboard、用户列表、尾程 Overview、`/dev/theme-states`；
- 页面无横向溢出，浮层定位正确，文字不截断，表格与分页可操作；
- 与参考原型和改造前基线分别截图，记录关键尺寸与差异性质。

完成定义：

- 默认 100% 下达到本规格中的关键尺寸；
- 三档显示比例均通过真实浏览器验证；
- 业务页面不新增通用视觉状态类；
- 状态矩阵和 guard 覆盖新增/改造组件；
- 全量前端门禁通过；
- 规格补齐实测证据后，方可宣称完成。
