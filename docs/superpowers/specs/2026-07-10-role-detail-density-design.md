# 角色详情区密度收敛设计

## 背景

“成员与部门”已使用统一的 `PageScaffold` / `DataTable` 密度，而“角色与权限”右侧详情区仍保留旧高保真原型的较大内距、标题和权限行高。当它与 Shell、Header 及成员表格同时出现时，角色详情会视觉上放大一档。

## 目标

- 以“成员与部门”为密度基准，收紧角色详情右栏。
- 保留角色标题、详情标签和权限分组的信息层级。
- 不改左侧角色列表，不改全局显示比例，不改 UI / Pro 基础组件的默认密度。
- 90% / 100% / 108% 三档显示比例下保持清晰、无溢出、无错位。

## 方案对比

### A. 右栏局部密度收敛（采用）

角色详情外层改用现有 `--page-scene-px` / `--page-scene-py` token；标题回到页内 `text-base` 层级；权限分组头使用 `--table-row-h`；资源行和权限动作使用紧凑间距与 `xs` 控件。数据权限页继续复用 `DataTable`，只收紧上方字段区和底部操作间距；角色成员卡片同步减少内距。

优点：修复根因，影响面最小，并且会自动跟随 flavor 和 `--app-scale`。

### B. 给右栏整体做 CSS 缩放（不采用）

通过 `transform: scale()` 或局部类似 zoom 的方式缩小内容。

问题：会造成字体清晰度、点击区域、滚动容器尺寸和 portal 定位不一致，也违反项目的 `--app-scale` 纪律。

### C. 下调全局表格/按钮 token（不采用）

修改 `--table-row-h`、`--control-sm` 等全局值。

问题：会连带改变已经合适的成员表格、Shell 和其他业务页，扩大了本次问题的影响面。

## 实现边界

### 角色详情外层

- `RolesScene` 右栏从硬编码 `px-7` / `22px` 切换到 `--page-scene-px` / `--page-scene-py`。
- `RoleDetailsPanel` 的角色标题降为 `text-base`，说明文本、标签区与内容区使用 12px–16px 的现有 spacing 节奏。
- 不改标签语义、权限判断、数据请求和滚动容器边界。

### 功能权限

- 工具条保持单行优先、可换行兜底，缩小组内间距。
- 权限分组头高度使用 `--table-row-h`，与数据表行密度同源。
- 资源行缩小纵向内距；权限动作使用 `Button size="xs"`，保留状态样式和键盘可达性。
- 不更改权限树的默认展开状态、搜索、全选、保存和草稿状态逻辑。

### 数据权限与角色成员

- 数据权限的 `DataTable` 保持不变，只收紧默认范围字段区和底部按钮区的外间距。
- 角色成员项缩小外层内距和间隔，保留头像、姓名、部门/职位与移除操作。

## 验收标准

1. 左侧角色列表的宽度、行高和交互不变。
2. 右栏页边距与“成员与部门”右栏来自同一组 `--page-scene-*` token。
3. 权限分组头与标准表格行来自同一 `--table-row-h` token；权限资源行高显著低于现状，且两行文字不裁切。
4. 角色标题、工具条、权限分组、资源名和次要 code 仍具有清晰层级。
5. 三个详情标签页的业务交互与数据流不变。
6. 新密度守卫先失败、实现后通过；再运行 `tsc`、`eslint`、`vitest`、`theme:guard` 和 90% / 100% / 108% 视觉采集。

## 非目标

- 不重设角色信息架构。
- 不修改左侧角色列表。
- 不修改全局 flavor、显示比例、字体或颜色 token。
- 不顺手改造角色 API、状态管理或其他 Admin 页。
