# 0727 启动排障与登录 Tab 焦点修复

## 全栈启动排障（三个独立故障）

- **问题**：`./scripts/dev.sh start` 失败。postgres / redis 起来了，后端起不来。
- **过程**：
  1. `modules/admin` 编译失败——`JooqLoginAuditWriter` 用了 `org.slf4j.*`，但 `modules/admin/pom.xml` 没声明 `slf4j-api`。父 pom 已 import `spring-boot-dependencies`，补依赖不用写版本。
  2. 编译失败后 `dev.sh` 拿 `target/` 里的**旧 jar** 继续启动，掩盖了第一个错误，暴露出第二个：`METABUILDER_DEPLOYMENT_MODE must be explicitly configured`。对比 `.env` 与 `.env.example` 的键名，本地 `.env` 缺 `METABUILDER_DEPLOYMENT_MODE` 和 `METABUILDER_BOOTSTRAP_ADMIN_PASSWORD`——`generate_local_env` 只在 `.env` 不存在时 `cp` 模板，已存在就不补新增键。
  3. 手动 `mvnw package` 验证修复时撞第三个：enforcer 报 `Detected JDK version 25.0.1 ... not in the allowed range [21,22)`。`dev.sh` 内部 `resolve_java_21` 会自己找 `/opt/homebrew/opt/openjdk@21`，但手跑 mvnw 走的是 shell 默认 JDK 25。
- **结论**：
  - `modules/admin/pom.xml` 补 `org.slf4j:slf4j-api`（无版本，BOM 管理）。
  - `backend/.env` 追加两个键，bootstrap 密码用于把 `mb_user` 里 `!bootstrap-credential-unset!` 的 sentinel 换成真 hash（见 `V2__create_iam_read_model.sql`），否则 admin 无法登录。
  - 手跑 mvnw 需先 `export JAVA_HOME=/opt/homebrew/opt/openjdk@21`。
  - e2e 验证到业务可用终态：登录拿 token → 经 vite proxy 的 `/api/auth/me` 返回 `SYSTEM_ADMIN` + 4 个权限点 → `/api/users` 返回真实 DB 数据。
  - 另记：开发态 `VITE_ENABLE_MOCK=true`，浏览器上走 MSW 而非真后端；mock 凭据 `admin` / `admin123`，真后端 `admin` / `.env` 里的 bootstrap 密码。
- **耗时**：约 20 分钟。

## 登录页 Tab 焦点顺序

- **问题**：焦点在账号输入框时按 Tab，跳到"忘记密码?"而不是密码输入框。
- **过程**：根因不是 tabindex，是 DOM 顺序——`忘记密码?` 写在密码 `<InputGroup>` **之前**（在 label 那一行的 flex 容器里），而 Tab 顺序只认 DOM 顺序。
  排除两个假修复：`tabIndex={-1}` 会让键盘用户彻底 Tab 不到该链接（可访问性倒退）；flex `order` 只换视觉不换 Tab 顺序（这类 bug 的经典误修）。
  先在 `auth-pages.test.tsx` 加守卫测试复现红（断言焦点落在 `login-password`），再改实现。
- **结论**：把按钮移到 `InputGroup` 之后，外层 `relative` + 按钮 `absolute right-0 top-0`；label 行显式 `h-[calc(24px*var(--app-scale))]` 保住原行高。
  验证：真浏览器 Tab 链 = 账号 → 密码 → 显示密码 → 忘记密码? → 登录；`getBoundingClientRect` 在 90/100/108 三档 `--app-scale` 下 `label.centerY == forgot.centerY`、`forgot.right == 容器.right`、均无横向溢出。全量门禁绿（tsc 0 错、eslint 0 错、vitest 117 文件 760 测试）。
  文件：`frontend/src/modules/admin/auth/list/LoginScene.tsx:335`
- **耗时**：约 20 分钟。

## 仪表盘密度诊断（分析，未落地）

- **问题**：洋哥拿一个第三方打单系统的订单详情页做参照，问为什么人家紧凑、我们的 dashboard 空。
- **过程**：把我们的页面在同尺寸视口（1990×1130）下用 DOM 实测，参照系只能从截图目测估算——口径已在结论里标明。
  实测数据：首屏可见文本单元 81（参照系约 109）；快捷入口相邻中心距 **279px** 装 48px 图标（横向利用率 17%）；KPI 卡 414×164、内部文字总高约 70px（垂直利用率 43%）；8 个卡片承载 81 个信息单元（参照系 5 个卡承载约 109）；字号跨 11–30px（参照系 12–15px）。
- **结论**：先剥离页面类型这个前置变量——详情页 vs 仪表盘的密度差有一部分是类型的正常表现，照搬详情页密度会做出"假装很忙"的仪表盘。剥离后剩下四条真问题：
  1. 空间平分而非内容驱动列宽（`grid-cols-6` 平铺在 1702px 上）；
  2. 层级靠字号跳跃而非字重 + 颜色（空间代价平方级）；
  3. 信息不压行（参照系大量用 `·` 把 2–4 个信息点并进一行）；
  4. 颜色预算花在导航装饰而非业务语义上。
  已提议按这四条改一版并出改造前后截图对比，等拍板。
- **耗时**：约 15 分钟。
